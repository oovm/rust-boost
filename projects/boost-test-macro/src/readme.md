# `boost-test-macro`

Procedural macros for `boost-test`.

`#[boost_test::test]` turns a free function into a standard `#[test]` entry that builds a
`TestDescriptor` and calls `boost_test::run`. The generated wrapper is ordinary Rust: the original body
keeps its name-derived source location, its `?` and `return` behaviour, and its result type.

Supported signatures without `fixture`:

- `fn name()`.
- `fn name(context: &mut boost_test::TestContext)`.
- Either form with a `Result<(), E>` return type, where `E: Display + 'static`.

With `fixture = path`, the wrapper calls `boost_test::run_with_fixture` instead. The body then takes the
fixture as a trailing `&mut Value`, optionally after `&mut boost_test::TestContext`:

- `fn name(value: &mut Value)`.
- `fn name(context: &mut boost_test::TestContext, value: &mut Value)`.
- Either form with a `Result<(), E>` return type.

Supported `test` attributes:

- `name = "..."` overrides the descriptor name without renaming the function.
- `case = "..."` attaches a stable `CaseId` to the descriptor.
- `fixture = path` names a fixture generated by `#[boost_test::fixture]`.
- `expected = "failure"` declares an expected failure. `expected = "pass"` is the default.
- `expected_failure` is a shorthand for `expected = "failure"`.

`#[boost_test::fixture]` turns a setup function into a typed fixture. The setup function may take no
arguments or one `&mut boost_test::TestContext` and returns either the value or `Result<Value, E>`. The
macro keeps the setup function callable and adds a marker type with the same name in the type
namespace, so `fixture = path` can name it. Supported fixture attributes:

- `name = "..."` overrides the fixture descriptor name.
- `teardown = path` names a teardown function that receives the value and returns `()` or
  `Result<(), E>`. The runner calls it after the body, including after a body panic, and appends its
  failure instead of replacing the body failure.

`#[boost_test::case]` expands one parameterized body into one standard `#[test]` entry per declared
case. Every entry is `"stable case name" => arguments`, separated by commas. A body with several
parameters receives a tuple with exactly that many elements; a body with one parameter receives the
expression itself. The case name becomes a `CaseId`, so the descriptor identity is
`module::name[case]`. Duplicate names, missing entries, arity mismatches, and invalid signatures are
rejected at compile time.

The macros reject `async`, generic, `const`, `unsafe`, `extern`, receiver-based, and non-unit result
signatures with a compile-time error at the offending span. Unsupported attributes such as `timeout`
and `trace` are rejected rather than silently ignored until their runtime contracts exist.
